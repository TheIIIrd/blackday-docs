# Шаг 10. Рабочее место администратора и хранилище секретов

> Проверено: Linux Mint Xfce Edition на ноутбуке 2011 года выпуска, сентябрь 2026.

**Машина:** старый ноутбук, которому не нашлось другого применения
**Система:** Linux Mint (Xfce Edition), чистая установка с полнодисковым шифрованием
**Роль:** администрирование и хранение секретов (пароли, SSH-ключи, ключи шифрования, репозиторий конфигов)

Идея шага: вынести все ключи и пароли на отдельную машину, которая не используется для повседневных задач. В тексте она называется `keeper`.

Дистрибутив принципиального значения не имеет — подойдёт любой, где установщик умеет полнодисковое шифрование. Mint выбран потому, что он неприхотлив к старому железу и долго поддерживается.

---

## Принципы, ради которых всё это делается

1. **Минимум софта.** Каждая лишняя программа, особенно сетевая, — это дополнительная поверхность атаки.
2. **Ничего не слушает сеть.** На ноутбук нельзя зайти снаружи: нет SSH-сервера, нет общих папок, нет обнаружения в сети.
3. **Диск зашифрован целиком.** Украденный или выброшенный ноутбук ничего не выдаёт.
4. **Всё важное существует минимум в двух экземплярах.** Ноутбук старый и может умереть в любой момент.
5. **Работа с секретами не зависит от интернета.** Всё хранится и открывается локально.

## 1. Подготовка установочной флешки (с другой рабочей машины)

### 1.1. Скачать образ и файлы проверки

С официального сайта Linux Mint (раздел Download → Xfce Edition) скачай:

- ISO-образ актуальной версии Xfce Edition (64-bit);
- `sha256sum.txt`;
- `sha256sum.txt.gpg`.

Все три файла положи в одну папку.

### 1.2. Проверить целостность и подпись

```bash
cd ~/Downloads   # или куда скачал

# 1. Контрольная сумма образа
sha256sum --ignore-missing -c sha256sum.txt
# Ожидаемый результат: linuxmint-...-xfce-64bit.iso: OK

# 2. Импорт ключа подписи Linux Mint
gpg --keyserver hkps://keyserver.ubuntu.com \
    --recv-keys 27DEB15644C6B3CF3BD7D291300F846BA25BAE09

# 3. Проверка подписи файла с суммами
gpg --verify sha256sum.txt.gpg sha256sum.txt
```

В выводе должно быть `Good signature from "Linux Mint ISO Signing Key"`. Предупреждение о том, что ключ «не заверен доверенной подписью», нормально. Сверь отпечаток ключа с тем, что опубликован на странице проверки образов на официальном сайте Mint: если он совпадает, образ подлинный.

**Почему это важно:** этот ноутбук будет хранить все ключи. Если система на нём с самого начала подменена, вся дальнейшая защита бессмысленна.

### 1.3. Записать образ на флешку

Найди флешку (смотри на размер и модель, чтобы не перепутать с диском):

```bash
lsblk -o NAME,SIZE,MODEL,TRAN
```

Запиши образ. **`/dev/sdX` замени на флешку. Ошибка в букве уничтожит данные на другом диске.**

```bash
sudo dd if=linuxmint-*-xfce-64bit.iso of=/dev/sdX bs=4M status=progress oflag=sync
```

## 2. BIOS и проверка диска

### 2.1. Настройки BIOS

Клавиша входа в BIOS зависит от производителя: чаще всего это F2, F10, Del или Esc, а меню выбора загрузочного устройства — F9, F11 или F12. Нужная клавиша обычно показана на экране в первую секунду после включения.

В BIOS:

1. Установи **пароль администратора BIOS** (Security → Administrator Password). Запиши его в бумажный конверт, в KeePassXC его положишь позже.
2. Если есть пункт Virtualization Technology, можно оставить как есть — он не мешает.
3. Сохрани и выйди.

### 2.2. Проверка здоровья диска

Ноутбук старый, и диск в нём, скорее всего, тоже. Прежде чем доверять ему секреты, проверим его. Загрузись с флешки, выбери запуск Live-системы и открой терминал.

#### Общая часть (для любого диска)

```bash
sudo apt-get update
sudo apt-get install -y smartmontools

lsblk -o NAME,SIZE,MODEL,ROTA,TRAN   # ROTA=1 — HDD, ROTA=0 — SSD
sudo smartctl -i /dev/sda            # модель, прошивка, поддержка SMART
sudo smartctl -H /dev/sda            # общий вердикт
```

`SMART overall-health self-assessment test result` должен быть `PASSED`. Но этого мало: диск часто пишет `PASSED` почти до самой смерти, поэтому дальше смотрим конкретные атрибуты. Какой раздел читать, определяет колонка `ROTA`.

Короткий самотест одинаков для обоих типов:

```bash
sudo smartctl -t short /dev/sda
# через 1–2 минуты:
sudo smartctl -l selftest /dev/sda
```

В результате должно быть `Completed without error`.

Для одного атрибута в обоих случаях правило общее: **`UDMA_CRC_Error_Count`** говорит не о самом диске, а о соединении (разъём, шлейф). Если он растёт, переподключи диск.

Подробный разбор столбцов вывода `smartctl` и атрибутов — в [reference/smart.md](../reference/smart.md).

#### Вариант А. HDD (ROTA=1)

```bash
sudo smartctl -A /dev/sda
```

| Атрибут | Что значит | Норма |
|---|---|---|
| `Reallocated_Sector_Ct` | сколько сбойных секторов уже заменено резервными | 0 |
| `Current_Pending_Sector` | «подозрительные» секторы, ожидающие переназначения | 0 |
| `Offline_Uncorrectable` | секторы, которые не удалось прочитать | 0 |
| `Reported_Uncorrect` | неисправимые ошибки чтения | 0 |
| `Power_On_Hours` | наработка в часах | для справки |

Единичные переназначенные секторы на старом диске терпимы, если число не растёт. Для этого запусти проверку ещё раз через несколько дней и сравни. Растущие `Reallocated` или ненулевые `Pending` и `Uncorrectable` означают, что диск умирает. Лучше сразу поставить недорогой SATA SSD: ноутбук заодно станет намного быстрее. Для задачи хватит 120–256 ГБ.

Если есть время (длится порядка часа или больше), полезен длинный тест: он читает всю поверхность и находит то, что короткий пропускает:

```bash
sudo smartctl -t long /dev/sda
sudo smartctl -c /dev/sda | grep -A1 'Extended self-test'   # ориентировочное время
# после завершения:
sudo smartctl -l selftest /dev/sda
```

#### Вариант Б. SSD (ROTA=0)

У SSD нет механики, зато есть износ ячеек памяти. Названия атрибутов у производителей разные, поэтому ищи по смыслу.

```bash
sudo smartctl -A /dev/sda   # атрибуты
sudo smartctl -x /dev/sda   # расширенный вывод, включая Device Statistics
```

**Износ (главное).** Атрибут может называться `Wear_Leveling_Count` (Samsung), `Media_Wearout_Indicator` (Intel), `Percent_Lifetime_Remain`, `SSD_Life_Left` или похоже. Смотри колонку `VALUE`: обычно это оставшийся ресурс в процентах, где 100 — новый диск. Надёжнее строка `Percentage Used Endurance Indicator` в разделе Device Statistics из вывода `smartctl -x`: там, наоборот, показан **израсходованный** ресурс.

| Израсходовано ресурса | Вывод |
|---|---|
| до ~70% | всё хорошо |
| 70–90% | работать можно, бэкапы обязательны |
| больше 90% | лучше заменить |

**Сколько записано.** `Total_LBAs_Written` (иногда `Host_Writes_GiB` или похоже). Если значение в LBA, умножь на 512 байт. Сравни с TBW (гарантированным объёмом записи) из спецификации модели — получится ещё одна оценка износа.

**Ошибки (должно быть 0 или близко к нулю):**

| Атрибут | Что значит |
|---|---|
| `Reallocated_Sector_Ct` / `Reallocated_Event_Count` | переназначенные блоки; единичные терпимы, растущие — плохой знак |
| `Reported_Uncorrect` / `Uncorrectable_Error_Cnt` | неисправимые ошибки; любое ненулевое значение настораживает |
| `Runtime_Bad_Block` | блоки, отказавшие во время работы |
| `Program_Fail_Count`, `Erase_Fail_Count` | сбои записи и стирания ячеек |

Длинный тест для SSD тоже существует (`smartctl -t long`), но он гораздо информативнее для HDD. Для SSD обычно достаточно атрибутов и короткого теста.

### 2.3. Только для SSD: очистка перед установкой

Если SSD раньше использовался, на нём могут остаться старые данные, и установщик затрёт их не полностью. Прямо с Live-флешки, **перед установкой**, пометь все ячейки как пустые:

```bash
lsblk -o NAME,SIZE,MODEL,ROTA   # ещё раз убедись, что это нужный диск
sudo blkdiscard /dev/sda
```

**Команда необратимо уничтожает всё на диске.** Работает за секунды и заодно даёт SSD «чистый» старт. Если она выдаст ошибку о том, что discard не поддерживается, пропусти этот шаг, он не критичен.

Для HDD этот шаг не нужен: `blkdiscard` к нему неприменим, а полная перезапись старого HDD идёт часами и в нашем сценарии избыточна, потому что новая установка всё равно зашифрована.

## 3. Установка

Подключи ноутбук **кабелем** к сети, если есть возможность: так надёжнее, чем Wi-Fi, и драйверы беспроводной карты не будут мешать установке.

На рабочем столе Live-системы запусти **Install Linux Mint**.

1. **Язык и раскладка** — по желанию.
2. **Мультимедиа-кодеки** — не ставь. На этой машине они не нужны.
3. **Тип установки** — выбери «Стереть диск и установить Linux Mint», затем нажми **«Дополнительные функции» (Advanced features)** и отметь:
   - **Использовать LVM**;
   - **Зашифровать новую установку Linux Mint**.
4. **Ключ шифрования** — длинная парольная фраза (5–6 случайных слов или длиннее). Это пароль, который вводится при каждой загрузке. Его нельзя восстановить: забудешь — данные потеряны.
5. **Пользователь:**
   - имя компьютера: `keeper`;
   - имя пользователя: любое;
   - пароль: отдельный от ключа шифрования;
   - выбери **«Требовать пароль для входа»**, не автоматический вход.

После установки извлеки флешку и перезагрузись. При загрузке должен появиться запрос парольной фразы диска.

## 4. Первая загрузка: проверки и обновления

### 4.1. Проверить, что шифрование действительно включено

```bash
lsblk -f
```

У одного из разделов (обычно `sda3` или похожего) должен быть тип `crypto_LUKS`, а внутри него — тома LVM с корнем и swap.

Посмотри детали шифрования (подставь свой раздел):

```bash
sudo cryptsetup luksDump /dev/sda3 | head -n 20
```

Ожидается `Version: 2` (LUKS2). В разделе Keyslots — `PBKDF: argon2id`. Если там `pbkdf2`, это не катастрофа, но стоит перевести слот на argon2id:

```bash
sudo cryptsetup luksConvertKey --pbkdf argon2id /dev/sda3
```

### 4.2. Резервная копия заголовка LUKS

Если заголовок LUKS повредится (сбой диска, ошибка при работе с разделами), расшифровать данные будет невозможно даже с правильным паролем. Сохраним его копию сейчас, а в разделе 13 она уедет на резервную флешку:

```bash
mkdir -p ~/vault/recovery
sudo cryptsetup luksHeaderBackup /dev/sda3 \
    --header-backup-file ~/vault/recovery/luks-header-keeper.img
sudo chown "$USER": ~/vault/recovery/luks-header-keeper.img
chmod 600 ~/vault/recovery/luks-header-keeper.img
```

### 4.3. Только для SSD: проверить TRIM

TRIM сообщает SSD, какие блоки свободны. Без него диск под LUKS со временем замедляется и изнашивается быстрее. В Mint периодический TRIM включён по умолчанию, но с шифрованием его нужно проверить по всей цепочке:

```bash
systemctl status fstrim.timer   # должен быть active (waiting)
cat /etc/crypttab               # в строке раздела должно быть discard
lsblk --discard                 # у зашифрованного тома и LVM ненулевые DISC-GRAN и DISC-MAX
```

Если в `/etc/crypttab` нет `discard`, добавь его в четвёртую колонку (опции), например `luks,discard`, затем:

```bash
sudo update-initramfs -u
sudo reboot
```

После перезагрузки проверь, что TRIM реально проходит:

```bash
sudo fstrim -av   # должен показать, сколько освобождено на /
```

Небольшая плата за это: снаружи можно увидеть, какие блоки диска пустые (но не их содержимое). Для этой задачи такой компромисс общепринят.

Для HDD этот раздел пропускается.

### 4.4. Уборка после установщика

Установщик Mint (ubiquity) в самом конце удаляет пакеты, нужные только live-системе. Этот шаг нередко отрабатывает не полностью, а установка при этом считается успешной. Самый частый след — пакет `casper` (это он в live-режиме отвечает за пункт меню «Check disc for defects»). На установленной системе носителя больше нет, служба падает, и это видно при выключении и в списке юнитов.

Проверь:

```bash
systemctl list-units --failed
dpkg -l | grep -i -E 'casper|ubiquity|live-boot'
```

Если `casper-md5check.service` в списке упавших, удали пакет. Сначала симуляция:

```bash
sudo apt-get -s purge casper
```

В плане должен быть только `casper` и, возможно, `localechooser-data` (список языков для установщика, работающей системе не нужен). **Останови операцию**, если увидишь `linux-image-*`, `systemd`, `xserver-*`, `xfce4-*`, `mint-*`, `network-manager` или `grub-*`.

Не путай `localechooser-data` с `locales` и `language-pack-*`: последние отвечают за локали работающей системы и нужны.

```bash
sudo apt-get purge casper
sudo apt-get autoremove --purge
sudo update-initramfs -u      # выкидывает хуки casper из образа ранней загрузки
sudo reboot
```

Перезагрузка здесь обязательна: `systemctl list-units --failed` показывает состояние с момента загрузки, поэтому упавший юнит остаётся в списке даже после удаления пакета. Сбросить его без перезагрузки можно через `sudo systemctl reset-failed`, но перезагрузка заодно проверяет, что система нормально стартует с пересобранным initramfs.

После перезагрузки:

```bash
systemctl list-units --failed                                # 0 loaded units listed
systemctl list-unit-files | grep -i casper                   # пусто
dpkg -l casper                                               # пакет не найден
lsinitramfs /boot/initrd.img-$(uname -r) | grep -i casper     # пусто
```

Если юнит всё ещё числится упавшим, посмотри, не остался ли симлинк:

```bash
ls -la /etc/systemd/system/ | grep -i casper
# при наличии: удалить симлинк, затем sudo systemctl daemon-reload
```

Причину сбоя установщика можно посмотреть в его логах:

```bash
sudo grep -riE 'casper|error|failed' /var/log/installer/ | tail -n 30
```

> **Про `apt` в Mint.** В Mint команда `apt` — это собственная обёртка (`/usr/local/bin/apt`), а не `apt` из Debian. Она понимает лишь свой набор команд и на незнакомый флаг просто печатает справку, ничего не выполняя. Поэтому там, где важны флаги (`-s`, `--dry-run`), зови `apt-get` или `/usr/bin/apt`. Проверить, что у тебя: `which -a apt`.

### 4.5. Обновление системы

```bash
sudo apt-get update
sudo apt-get full-upgrade -y
sudo reboot
```

### 4.6. Автоматические обновления безопасности

Открой **Менеджер обновлений → Правка → Параметры → Автоматизация** и включи:

- автоматическое применение обновлений;
- автоматическое удаление устаревших ядер и зависимостей.

### 4.7. Драйверы

Открой **Менеджер драйверов**. Если он предлагает драйвер для Wi-Fi (на g7 бывают карты Broadcom), поставь его. Проприетарный видеодрайвер не нужен.

## 5. Уменьшаем поверхность атаки

### 5.1. Удалить сетевые программы, которые здесь не нужны

Сначала посмотри, что из этого реально установлено:

```bash
dpkg -l | grep -E 'warpinator|transmission|hexchat|thunderbird|cups-browsed'
```

Удали то, что нашлось:

```bash
sudo apt-get purge -y warpinator transmission-gtk transmission-common hexchat thunderbird cups-browsed
sudo apt-get autoremove --purge -y
```

Что это и почему удаляем:

| Пакет | Что делает | Почему не нужен |
|---|---|---|
| `warpinator` | обмен файлами по локальной сети | открывает порт и принимает файлы от других устройств |
| `transmission-*` | торрент-клиент | сетевой сервис, не нужен |
| `hexchat` | IRC-клиент | не нужен |
| `thunderbird` | почта | почта на машине с ключами — прямой путь для фишинга |
| `cups-browsed` | автопоиск сетевых принтеров | слушает сеть, в нём находили серьёзные уязвимости |

### 5.2. Отключить ненужные службы

```bash
# Bluetooth — не нужен
sudo systemctl disable --now bluetooth.service

# Avahi (mDNS) — рассказывает всей сети о компьютере
sudo systemctl disable --now avahi-daemon.service avahi-daemon.socket
sudo systemctl mask avahi-daemon.service avahi-daemon.socket

# Печать — если не собираешься печатать с этого ноутбука
sudo systemctl disable --now cups.service cups.socket cups.path
```

Если печатать всё же понадобится, службы CUPS можно включить обратно командой `sudo systemctl enable --now cups.service`.

### 5.3. Убедиться, что SSH-сервера нет

На Mint его нет по умолчанию, но проверим:

```bash
dpkg -l openssh-server 2>/dev/null | grep ^ii && echo "SSH-сервер установлен — удали его" || echo "OK: SSH-сервера нет"
```

Если установлен: `sudo apt-get purge -y openssh-server`.

## 6. Файрвол

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw enable
sudo ufw status verbose
```

Ожидается `Status: active` и `Default: deny (incoming), allow (outgoing)`.

### Проверка: ничего не слушает сеть

```bash
sudo ss -tulpn
```

В идеале всё, что осталось, слушает только `127.0.0.1`, `127.0.0.53` (системный DNS) или `[::1]`. Колонка Peer Address со значением `0.0.0.0:*` или `[::]:*` означает лишь «принимает от любого собеседника», смотреть нужно на Local Address. Если в Local Address встретится `0.0.0.0` или `*`, выясни, чей это процесс (`ps -p PID -o comm=`), и реши, нужна ли тебе эта служба.

## 7. Блокировка экрана и сессия

**Настройки → Хранитель экрана (Xfce Screensaver):**

- блокировать экран через 5 минут бездействия;
- блокировать при включении хранителя экрана.

**Настройки → Управление питанием:**

- при закрытии крышки — блокировать экран (или уход в сон с блокировкой).

Правило: **уходишь надолго или уносишь ноутбук — выключай его полностью, а не усыпляй.** Пока ноутбук включён (даже во сне), ключ шифрования диска находится в оперативной памяти. Выключенный ноутбук защищён полностью.

## 9. KeePassXC

### 9.1. Создать базу

```bash
mkdir -p ~/vault
chmod 700 ~/vault
```

Запусти KeePassXC → **Создать новую базу данных**:

- расположение: `~/vault/main.kdbx`;
- **шифрование:** KDBX 4, алгоритм ключа **Argon2id**. Ползунком выставь время расшифровки около 1–2 секунд — на старом процессоре этого достаточно, и открытие не будет раздражать;
- **пароль:** длинная парольная фраза, **отличная** от пароля диска и пароля пользователя.

Ключевой файл пока не добавляй. Его легко потерять, а пользы на этом этапе немного. Вернёмся к нему вместе с аппаратными токенами.

### 9.2. Настройки безопасности

**Инструменты → Настройки → Безопасность:**

- очищать буфер обмена через 10 секунд;
- блокировать базу после 5 минут бездействия;
- блокировать базу при блокировке экрана.

### 9.3. Структура базы

Заведи группы:

```text
main.kdbx
├── Recovery      # пароль диска, пароль BIOS, коды восстановления
├── Home          # роутер, PPPoE, Pi, ПК, будущие серверы
├── VPS           # хостинг-провайдер, root/пользователь VPS, домен
├── Keys          # парольные фразы SSH-ключей и age
└── Personal      # всё остальное
```

Сразу занеси: пароль шифрования диска, пароль пользователя, пароль BIOS, данные PPPoE, пароль роутера, данные VPS и аккаунта у хостинг-провайдера.

## 10. SSH-ключи

### 10.1. Создать ключи

Отдельный ключ на каждую зону. Если один скомпрометирован, другие зоны остаются в безопасности.

```bash
mkdir -p ~/.ssh
chmod 700 ~/.ssh

ssh-keygen -t ed25519 -C "keeper→home" -f ~/.ssh/id_home
ssh-keygen -t ed25519 -C "keeper→vps"  -f ~/.ssh/id_vps
```

Каждому ключу — **своя парольная фраза**. Сохрани их в KeePassXC, группа Keys.

### 10.2. Конфиг SSH

Файл `~/.ssh/config`:

```sshconfig
# Общие настройки для всех хостов
Host *
    IdentitiesOnly yes
    AddKeysToAgent yes
    ServerAliveInterval 30
    ServerAliveCountMax 3
    HashKnownHosts yes

# Домашняя сеть
Host pi
    HostName 192.0.2.X          # адрес одноплатника — задаётся в шаге 20
    User admin
    IdentityFile ~/.ssh/id_home

# VPS
Host vps
    HostName VPS_IP_OR_DOMAIN
    User admin
    Port 22                       # поменяем, когда настроим VPS
    IdentityFile ~/.ssh/id_vps
```

```bash
chmod 600 ~/.ssh/config
```

`IdentitiesOnly yes` важен: без него SSH предлагает серверу все ключи подряд, и VPS узнаёт о существовании твоего домашнего ключа.

## 11. age и sops: ключ для шифрования секретов в репозитории


Команда выведет строку вида:

### 12.4. Защита от случайного коммита незашифрованного секрета

Самая частая ошибка при работе с sops — создать файл в `secrets/` обычным редактором и закоммитить его в открытом виде. Хук ниже не даст этого сделать: он проверяет, что каждый YAML-файл в `secrets/`, попадающий в коммит, содержит служебный блок sops.

Файл `~/blackday/tools/pre-commit`:

```bash
#!/usr/bin/env bash
# Блокирует коммит незашифрованных файлов из secrets/.
# Зашифрованный sops YAML всегда содержит служебный ключ верхнего уровня "sops:".
set -euo pipefail

fail=0
while IFS= read -r f; do
    case "$f" in
        secrets/*.yaml)
            if ! git show ":$f" | grep -q '^sops:'; then
                echo "ОШИБКА: $f не зашифрован sops. Используй: sops $f" >&2
                fail=1
            fi
            ;;
        secrets/*)
            echo "ОШИБКА: в secrets/ допускаются только .yaml, зашифрованные sops: $f" >&2
            fail=1
            ;;
    esac
done < <(git diff --cached --name-only --diff-filter=ACMR)

exit "$fail"
```

Подключить хук:

```bash
chmod +x ~/blackday/tools/pre-commit
ln -s ../../tools/pre-commit ~/blackday/.git/hooks/pre-commit
```

Хук лежит в самом репозитории (`tools/`), поэтому переживёт переезд на другую машину — после клонирования достаточно заново сделать символическую ссылку.

### 12.5. Проверка, что всё работает

```bash
cd ~/blackday

# 1. Зашифрованный секрет — должен закоммититься
sops secrets/test.yaml
#   В открывшемся редакторе напиши, например:  test_password: hello
#   Сохрани и закрой.
cat secrets/test.yaml        # на диске должна быть шифровка (ENC[AES256_GCM,...])
sops -d secrets/test.yaml    # а так — открытый текст

# 2. Незашифрованный секрет — хук должен его остановить
echo "plain: oops" > secrets/plain.yaml
git add secrets/plain.yaml
git commit -m "test"         # ожидается ОШИБКА от хука
git rm --cached secrets/plain.yaml
rm secrets/plain.yaml

# 3. Первый настоящий коммит
git add .
git commit -m "Инициализация репозитория blackday"
```

После проверки тестовый секрет можно удалить (`git rm secrets/test.yaml && git commit -m "Удалить тестовый секрет"`) или оставить.

## 13. Резервная флешка

Нужна отдельная флешка, которая будет храниться **не рядом с ноутбуком**. На неё копируется всё, без чего нельзя восстановиться.

### 13.1. Подготовка (один раз)

**Все данные на флешке будут уничтожены. Проверь букву устройства.**

```bash
lsblk -o NAME,SIZE,MODEL,TRAN

# Один раздел на всю флешку
sudo parted /dev/sdX --script mklabel gpt mkpart backup 1MiB 100%

# Шифрование: отдельная парольная фраза, сохрани её в KeePassXC → Recovery
# и дополнительно на бумаге (без бумажной копии флешка бесполезна,
# если погибнет ноутбук вместе с базой)
sudo cryptsetup luksFormat --type luks2 /dev/sdX1

sudo cryptsetup open /dev/sdX1 backup_usb
sudo mkfs.ext4 -L keeper-backup /dev/mapper/backup_usb
sudo mkdir -p /mnt/backup
sudo mount /dev/mapper/backup_usb /mnt/backup
sudo chown "$USER": /mnt/backup
sudo umount /mnt/backup
sudo cryptsetup close backup_usb
```

### 13.2. Скрипт бэкапа

Файл `~/blackday/tools/backup-keeper.sh`:

```bash
#!/usr/bin/env bash
# Бэкап секретов keeper на зашифрованную флешку.
# Использование: backup-keeper.sh /dev/sdX1
set -euo pipefail

DEV="${1:?Укажи раздел флешки, например: $0 /dev/sdb1}"
MAPPER=backup_usb
MNT=/mnt/backup
KEEP=10   # сколько последних снимков хранить

cleanup() {
    mountpoint -q "$MNT" && sudo umount "$MNT"
    [[ -e "/dev/mapper/$MAPPER" ]] && sudo cryptsetup close "$MAPPER"
}
trap cleanup EXIT

sudo cryptsetup open "$DEV" "$MAPPER"
sudo mkdir -p "$MNT"
sudo mount "/dev/mapper/$MAPPER" "$MNT"

STAMP="$(date +%Y-%m-%d_%H%M%S)"
DEST="$MNT/snapshots/$STAMP"
mkdir -p "$DEST"

# Секреты и ключи
rsync -a "$HOME/vault/"            "$DEST/vault/"
rsync -a "$HOME/.ssh/"             "$DEST/ssh/"
rsync -a "$HOME/.config/sops/age/" "$DEST/age/"

# Репозиторий целиком одним файлом (вся история, все ветки)
git -C "$HOME/blackday" bundle create "$DEST/blackday.bundle" --all

# Контрольные суммы, чтобы при восстановлении можно было проверить целостность
( cd "$DEST" && find . -type f ! -name SHA256SUMS -print0 | sort -z | xargs -0 sha256sum > SHA256SUMS )

sync
echo "Снимок сохранён: $STAMP"

# Удаление старых снимков, оставляем $KEEP последних
mapfile -t old < <(ls -1d "$MNT"/snapshots/*/ | sort | head -n -"$KEEP")
for d in "${old[@]}"; do
    rm -rf -- "$d"
    echo "Удалён старый снимок: $(basename "$d")"
done

df -h "$MNT" | tail -n 1
```

```bash
chmod +x ~/blackday/tools/backup-keeper.sh
~/blackday/tools/backup-keeper.sh /dev/sdX1
```

### 13.3. Проверка восстановления

Бэкап, который ни разу не восстанавливали, — это надежда, а не бэкап. Один раз проверь:

```bash
sudo cryptsetup open /dev/sdX1 backup_usb
sudo mount /dev/mapper/backup_usb /mnt/backup
cd /mnt/backup/snapshots/$(ls -1 /mnt/backup/snapshots | tail -n 1)

sha256sum -c SHA256SUMS                       # все файлы: OK
git clone blackday.bundle /tmp/restore-test   # репозиторий восстанавливается
ls /tmp/restore-test

cd ~ && rm -rf /tmp/restore-test
sudo umount /mnt/backup && sudo cryptsetup close backup_usb
```

### 13.4. Когда делать бэкап

- после каждого важного изменения (новый ключ, новый пароль, новый хост);
- в любом случае — раз в пару недель.

## 15. Правила эксплуатации

1. **Не используй keeper как обычный компьютер.** Никакого браузинга, почты, мессенджеров, игр. Браузер — только для веб-интерфейсов своих устройств (роутер, Pi-hole, панель хостинга).
2. **Ничего не ставь из сторонних источников** без крайней необходимости и проверки подписи или контрольной суммы.
3. **Уходишь — выключай**, а не усыпляй.
4. **Сделал важное изменение — сделай бэкап.**
5. **Флешку с бэкапом и бумажный конверт храни отдельно** от ноутбука и друг от друга, если возможно.
6. **Не подключай к keeper чужие флешки.**
