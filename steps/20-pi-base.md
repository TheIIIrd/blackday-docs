# Шаг 20. Базовая настройка одноплатника

> Проверено: Raspberry Pi OS Lite (64-bit) на Raspberry Pi 5, сентябрь 2026.

**Машина:** Raspberry Pi 5 (8 ГБ), SD-карта на 128 ГБ
**Система:** Raspberry Pi OS Lite (64-bit), без графического окружения
**Результат шага:** чистая, обновлённая и защищённая Pi со статическим адресом, доступом по SSH только по ключу с keeper, файрволом, точным временем (NTP-сервер для всей сети) и бережным отношением к SD-карте. Плюс полный образ карты, из которого система восстанавливается за несколько минут.

Pi-hole и Unbound здесь **не ставятся** — это шаг 30. Сейчас готовим надёжный фундамент под них.

## 0. Что понадобится

- Raspberry Pi 5 и **официальный блок питания 27 Вт** (5,1 В / 5 А). С обычными зарядками Pi 5 ограничивает ток на USB, а это критично, когда к ней подключён телефон как резервный канал.
- **Охлаждение.** Без него Pi 5 под нагрузкой сбрасывает частоту. Подойдёт официальный Active Cooler или корпус с вентилятором.
- SD-карта и картридер (в HP g7 он встроенный).
- Ethernet-кабель до роутера.
- **Необязательно, но желательно:** батарейка для часов реального времени — официальная Raspberry Pi RTC Battery (перезаряжаемая, ML-2020 с разъёмом JST). Подключается в разъём BAT на плате.

**Если на SD-карте сейчас что-то есть** и оно тебе нужно, сохрани это до начала: карта будет полностью перезаписана.

## 1. Запись системы на карту

### 1.1. Где запускать Raspberry Pi Imager

Удобнее всего — на обычной рабочей машине со свежим дистрибутивом, например:

```bash
sudo pacman -S rpi-imager   # Arch
sudo apt install rpi-imager # Debian/Ubuntu/Mint
```

Версия важна: новые образы Raspberry Pi OS настраиваются при первой загрузке иначе, чем старые, и **устаревший Imager может записать образ, но не применить настройки** (пользователя, SSH-ключ). В репозиториях Debian, Ubuntu и Mint Imager нередко отстаёт от актуальной версии — проверь `rpi-imager --version` и при необходимости возьми свежую сборку с сайта проекта.

Imager понадобится твой **публичный** ключ `~/.ssh/id_home.pub` с keeper (создан в [шаге 10](10-keeper.md)). Публичный ключ не секрет, его можно перенести на своей флешке или просто открыть файл и скопировать. Приватный ключ (`id_home` без `.pub`) с keeper **не выносится никогда**.

### 1.2. Выбор образа

В Imager:

1. **Устройство:** Raspberry Pi 5.
2. **ОС:** Raspberry Pi OS (other) → **Raspberry Pi OS Lite (64-bit)**.
3. **Накопитель:** твоя SD-карта. Проверь размер (около 119 ГиБ для карты на 128 ГБ), чтобы не перепутать с другим диском.

Imager сам скачивает образ с официального сервера и проверяет его контрольную сумму, поэтому ручная проверка здесь не нужна.

### 1.3. Настройки образа

Перед записью Imager предложит настроить образ. Названия пунктов немного различаются между версиями, суть такая:

| Параметр | Значение |
|---|---|
| Имя хоста | `pi` |
| Пользователь | `admin` (не `pi`: стандартное имя — первое, что перебирают боты) |
| Пароль | длинный, **сохрани в KeePassXC → Home**. Он понадобится для `sudo` |
| Wi-Fi | **не настраивать** — Pi работает по кабелю |
| Часовой пояс и раскладка | свои |
| SSH | **включить**, способ — **только по публичному ключу**, вставить содержимое `id_home.pub` |
| Raspberry Pi Connect и прочие облачные сервисы | **выключить** |

Запиши образ.

## 2. Первый вход

### 2.1. Узнать адрес Pi

Вставь карту в Pi, подключи кабель к роутеру, затем питание. Первая загрузка длится дольше обычного (минуту-две), потому что система расширяет раздел и применяет настройки.

Если на keeper отключён mDNS (Avahi), как в [шаге 10](10-keeper.md), имя `pi.local` работать не будет — это нормально. Адрес смотрим в веб-интерфейсе роутера (только чтение, ничего не меняем): **LuCI → Status → Overview → Active DHCP Leases**. Найди строку с именем `pi`.

### 2.2. Подключиться

Временно, пока адрес динамический, в `~/.ssh/config` на keeper подставь адрес из DHCP:

```sshconfig
Host pi
    HostName 192.0.2.XXX    # адрес из списка DHCP; в разделе 4 станет постоянным
    User admin
    IdentityFile ~/.ssh/id_home
```

```bash
ssh pi
```

При первом подключении SSH покажет отпечаток ключа хоста и спросит, доверять ли ему. В домашней сети вероятность подмены мала, и обычно достаточно ответить `yes`.

**Если хочешь сделать строго** (так принято для машины с секретами), сверь отпечаток до ответа: подключи к Pi монитор (micro-HDMI) и клавиатуру, войди локально и выполни:

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Отпечаток должен совпасть с тем, что показывает SSH на keeper.

## 3. Обновление системы и прошивки

```bash
sudo apt update
sudo apt full-upgrade -y

# Прошивка загрузчика (EEPROM) Pi 5
sudo rpi-eeprom-update        # покажет текущую и доступную версию
sudo rpi-eeprom-update -a     # применить, если есть обновление

sudo reboot
```

После перезагрузки проверь питание и температуру:

```bash
vcgencmd get_throttled   # должно быть throttled=0x0
vcgencmd measure_temp    # в простое обычно 40–55 °C с активным охлаждением
```

Любое значение `get_throttled`, кроме `0x0`, означает проблемы с питанием или перегрев (бит 0 — недостаточное напряжение прямо сейчас, бит 16 — недостаточное напряжение было с момента загрузки). Частая причина — неофициальный блок питания или плохой кабель.

## 4. Статический адрес

Pi — сетевая инфраструктура: на ней будут DNS, NTP, а позже, возможно, и DHCP. Её адрес не должен меняться. Задаём его **на самой Pi**, а не резервированием на роутере: так Pi не зависит от роутера, и позже, если DHCP переедет на Pi, ничего не сломается.

### 4.1. Выбрать адрес

На Pi посмотри текущие параметры сети:

```bash
ip -4 addr show eth0     # адрес и маска, например 192.0.2.123/24 → подсеть 192.0.2.0/24
ip route | grep default  # шлюз, например default via 192.0.2.1
```

Теперь узнай диапазон DHCP на роутере (только смотрим): **LuCI → Network → Interfaces → LAN → Edit → DHCP Server**. Поля **Start** и **Limit** задают диапазон. По умолчанию в OpenWrt Start = 100, Limit = 150, то есть адреса с `.100` по `.249` раздаёт DHCP.

Адрес для Pi выбери **вне этого диапазона**, например `192.0.2.10`. Убедись, что он свободен:

```bash
ping -c 3 192.0.2.10    # ответов быть не должно
```

### 4.2. Назначить адрес

Raspberry Pi OS управляет сетью через NetworkManager. Узнай имя проводного подключения:

```bash
nmcli -t -f NAME,DEVICE con show
```

Имя может быть `Wired connection 1`, `netplan-eth0` или похожее — используй то, что показано для `eth0`. Ниже оно обозначено как `ИМЯ`.

**Внимание:** после применения SSH-сессия оборвётся, потому что у Pi сменится адрес. Это ожидаемо. Если что-то пойдёт не так и Pi пропадёт из сети, подключи монитор и клавиатуру и исправь настройки локально.

```bash
sudo nmcli con mod "ИМЯ" \
    ipv4.method manual \
    ipv4.addresses 192.0.2.10/24 \
    ipv4.gateway 192.0.2.1 \
    ipv4.dns 192.0.2.1

sudo nmcli con up "ИМЯ"
```

DNS пока указывает на роутер. На шаге 2 Pi начнёт обслуживать DNS сама. IPv6 не трогаем: с ним разберёмся на шаге 2.

### 4.3. Переподключиться и проверить

На keeper поправь `~/.ssh/config`:

```sshconfig
Host pi
    HostName 192.0.2.10
    User admin
    IdentityFile ~/.ssh/id_home
```

```bash
ssh pi
ip -4 addr show eth0          # должен быть новый адрес
ping -c 3 1.1.1.1             # интернет работает
ping -c 3 debian.org          # DNS работает
```

**Обязательно перезагрузи Pi и проверь ещё раз**, что адрес сохранился:

```bash
sudo reboot
# через минуту:
ssh pi 'ip -4 addr show eth0'
```

## 5. Часы, часовой пояс и NTP-сервер для сети

### 5.1. Часовой пояс

```bash
sudo timedatectl set-timezone Region/City
timedatectl
```

### 5.2. Часы реального времени (RTC)

У Pi 5 есть встроенные часы, но без батарейки они сбрасываются при отключении питания. После загрузки без интернета Pi окажется в прошлом, и на шаге 2 это сломает проверку DNSSEC.

Проверить, что часы видны системе:

```bash
ls /dev/rtc0
timedatectl | grep 'RTC time'
```

**Если поставил официальную перезаряжаемую батарейку**, включи её подзарядку. Добавь в конец файла `/boot/firmware/config.txt`:

```ini
# Подзарядка перезаряжаемой батарейки RTC (только ML-2020 / официальная RTC Battery!)
dtparam=rtc_bbat_vchg=3000000
```

> **Не включай подзарядку для обычной батарейки CR2032** или любой неперезаряжаемой: она может вздуться или потечь. Если батарейка неперезаряжаемая, эту строку не добавляй вовсе.

Перезагрузка и проверка:

```bash
sudo reboot
# после загрузки:
cat /sys/devices/platform/soc/soc:rpi_rtc/rtc/rtc0/charging_voltage 2>/dev/null
# ожидается 3000000
```

(Если по этому пути файла нет, пропусти проверку: путь в sysfs может отличаться между версиями ядра. Главная проверка — тест без интернета ниже.)

**Проверка без интернета** (после того как Pi поработала с батарейкой хотя бы несколько часов, чтобы та зарядилась): выключи Pi (`sudo poweroff`), отключи питание и сетевой кабель на несколько минут, затем включи **без кабеля**, подключи монитор и выполни `date`. Время должно быть правильным.

### 5.3. chrony: точное время для всей сети

Вместо стандартного `systemd-timesyncd` ставим chrony. Он умеет раздавать время другим устройствам, а при обрыве интернета продолжит это делать, опираясь на RTC.

```bash
sudo apt install -y chrony    # systemd-timesyncd удалится автоматически
```

Создай файл `/etc/chrony/conf.d/10-lan.conf` (готовая копия — [snippets/chrony/10-lan.conf](../snippets/chrony/10-lan.conf)):

```conf
# Раздавать время устройствам домашней сети
allow 192.0.2.0/24

# Продолжать раздавать время, даже если внешние NTP-серверы недоступны.
# Опирается на собственные часы Pi (с батарейкой RTC — надёжно).
local stratum 10
```

```bash
sudo systemctl restart chrony
chronyc tracking     # Leap status: Normal, System time — доли секунды
chronyc sources -v   # список серверов, у выбранного стоит ^*
```

Клиенты в сети начнут пользоваться этим сервером позже. На этом шаге важно только, что Pi сама держит точное время.

> **Про `local stratum 10`:** без батарейки RTC эта строка опасна — после отключения питания Pi может раздавать сети неправильное время. Если батарейки пока нет, закомментируй строку и вернись к ней, когда поставишь батарейку.

## 6. SSH: только ключи, никакого root

### 6.1. Настройки сервера

Создай файл `/etc/ssh/sshd_config.d/10-hardening.conf` (готовая копия — [snippets/sshd/10-hardening.conf](../snippets/sshd/10-hardening.conf)):

```conf
# Только вход по ключу
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
AuthenticationMethods publickey

# Без входа под root, только наш пользователь
PermitRootLogin no
AllowUsers admin

# Меньше возможностей для перебора и злоупотреблений
MaxAuthTries 3
LoginGraceTime 30
X11Forwarding no
```

Имя начинается с `10-` не случайно: sshd применяет **первое** найденное значение каждого параметра, а файлы в `sshd_config.d` читаются по алфавиту. Так наши настройки гарантированно побеждают файлы, которые создаёт система при первой загрузке (например, `50-cloud-init.conf`).

### 6.2. Применить безопасно

**Не закрывай текущую SSH-сессию до конца проверки.** Если что-то пойдёт не так, она останется твоим способом всё исправить.

```bash
# 1. Проверка синтаксиса — не должно быть вывода
sudo sshd -t

# 2. Проверка итоговых значений
sudo sshd -T | grep -Ei '^(passwordauthentication|kbdinteractiveauthentication|permitrootlogin|authenticationmethods|allowusers)'
# Ожидается: passwordauthentication no, kbdinteractiveauthentication no,
#            permitrootlogin no, authenticationmethods publickey, allowusers admin

# 3. Применить
sudo systemctl reload ssh
```

**Во втором окне терминала** на keeper проверь:

```bash
ssh pi 'echo OK'                                   # вход по ключу работает
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password pi
# должно быть: Permission denied (publickey)
```

Только после этого можно закрыть первую сессию.

### 6.3. sudo с паролем

По умолчанию Raspberry Pi OS даёт первому пользователю `sudo` без пароля. На машине, которая станет центром сети, это лишнее: украденная SSH-сессия сразу получает root. Посмотри, есть ли такой файл:

```bash
ls /etc/sudoers.d/
cat /etc/sudoers.d/010_* 2>/dev/null   # ищи строку с NOPASSWD
```

Сначала убедись, что пароль пользователя работает:

```bash
sudo -k          # сбросить кэш sudo
sudo true        # должен запросить пароль и принять его
```

Если пароль принят, удали файл с `NOPASSWD` (подставь точное имя из `ls`):

```bash
sudo rm /etc/sudoers.d/010_pi-nopasswd
```

**В новой сессии** проверь, что `sudo` по-прежнему работает, но спрашивает пароль:

```bash
ssh pi
sudo -k && sudo true
```

## 7. Лишние службы и радиомодули

Pi работает по кабелю, поэтому Wi-Fi и Bluetooth не нужны. Добавь в конец `/boot/firmware/config.txt`:

```ini
# Pi работает по Ethernet: радиомодули не нужны
dtoverlay=disable-wifi
dtoverlay=disable-bt
```

Это обратимо: достаточно удалить строки и перезагрузиться.

Отключи службы, которые больше не нужны:

```bash
sudo systemctl disable --now bluetooth.service 2>/dev/null
sudo systemctl disable --now hciuart.service 2>/dev/null
sudo systemctl disable --now avahi-daemon.service avahi-daemon.socket 2>/dev/null
```

**ModemManager** пока не трогаем. Для телефона по USB и модема в режиме HiLink он не нужен, но решение о нём примем на шаге с резервным каналом.

Посмотри, что ещё запущено и слушает сеть:

```bash
systemctl list-units --type=service --state=running
sudo ss -tulpn
```

На этом этапе снаружи должны быть доступны только SSH (порт 22) и chrony (UDP 123). Если видишь что-то ещё, пришли мне вывод.

## 8. Файрвол (nftables)

### 8.1. Правила

```bash
sudo apt install -y nftables
```

Файл `/etc/nftables.conf` (готовая копия — [snippets/nftables/pi-base.nft](../snippets/nftables/pi-base.nft)):

```nft
#!/usr/sbin/nft -f
# Файрвол одноплатника — шаг 20: только SSH и NTP из домашней сети.
flush ruleset

define LAN4 = 192.0.2.0/24

table inet filter {
    chain input {
        type filter hook input priority filter; policy drop;

        # Ответы на наши собственные соединения
        ct state established,related accept
        ct state invalid drop

        # Локальные процессы
        iif "lo" accept

        # ICMP и ICMPv6: ping, диагностика, а для IPv6 это ещё и обнаружение
        # соседей (без ICMPv6 IPv6 просто перестаёт работать)
        meta l4proto { icmp, ipv6-icmp } accept

        # SSH — только из домашней сети
        ip  saddr $LAN4     tcp dport 22  accept
        ip6 saddr fe80::/10 tcp dport 22  accept

        # NTP-сервер для домашней сети
        ip  saddr $LAN4     udp dport 123 accept
    }

    chain forward {
        type filter hook forward priority filter; policy drop;
        # Маршрутизации пока нет. Появится, когда Pi станет шлюзом.
    }

    chain output {
        type filter hook output priority filter; policy accept;
    }
}
```

### 8.2. Применить с автоматическим откатом

Ошибка в правилах файрвола может закрыть тебе доступ к Pi. Поэтому применяем правила с «таймером безопасности»: если в течение двух минут ты не подтвердишь, что доступ есть, правила сами сбросятся.

```bash
# 1. Проверка синтаксиса без применения
sudo nft -c -f /etc/nftables.conf && echo "Синтаксис OK"

# 2. Таймер отката: через 120 секунд сбросить все правила
sudo systemd-run --on-active=120 --unit=nft-rollback /usr/sbin/nft flush ruleset

# 3. Применить правила
sudo nft -f /etc/nftables.conf
```

**Сразу же в новом окне** на keeper:

```bash
ssh pi 'echo OK'
```

Если вход работает — отмени откат и включи файрвол при загрузке:

```bash
sudo systemctl stop nft-rollback.timer
sudo systemctl enable --now nftables.service
sudo nft list ruleset
```

Если вход не работает — просто подожди две минуты: правила сбросятся, и можно будет разобраться.

### 8.3. Проверка

```bash
sudo reboot
# после загрузки:
ssh pi 'sudo nft list ruleset | head -n 5'   # правила загружены
chronyc -h 192.0.2.10 tracking             # с keeper: NTP отвечает (если на keeper есть chrony)
```

Если на keeper нет chrony, проверку NTP можно отложить: клиенты будут подключаться к нему позже.

## 9. Бережём SD-карту

SD-карты изнашиваются от постоянной записи. Главные источники записи на Pi — логи, swap и служебные метки времени файлов.

### 9.1. Логи в оперативной памяти

Создай файл `/etc/systemd/journald.conf.d/10-volatile.conf` (готовая копия — [snippets/journald/10-volatile.conf](../snippets/journald/10-volatile.conf)):

```ini
[Journal]
# Хранить журнал только в RAM — не пишем на SD-карту
Storage=volatile
RuntimeMaxUse=64M
```

```bash
sudo mkdir -p /etc/systemd/journald.conf.d
# (создай файл выше, затем:)
sudo systemctl restart systemd-journald
journalctl --disk-usage
```

**Цена решения:** после перезагрузки логи предыдущей сессии пропадают, и разобраться, почему Pi внезапно перезагрузилась, будет сложнее. Для Pi на SD-карте это разумный компромисс. Когда Pi переедет на NVMe, вернём постоянный журнал. Позже можно также настроить отправку логов на ПК или сервер.

Если на системе остался классический rsyslog (он пишет те же логи второй раз в `/var/log`), отключи его:

```bash
systemctl is-active rsyslog && sudo systemctl disable --now rsyslog
```

### 9.2. Swap

```bash
swapon --show
```

- Если там `/dev/zram0` — это сжатый swap в оперативной памяти, **на карту он не пишет**, оставляем.
- Если там файл, например `/var/swap`, — это swap на SD-карте. С 8 ГБ ОЗУ он не нужен, отключаем:

```bash
sudo dphys-swapfile swapoff 2>/dev/null
sudo systemctl disable --now dphys-swapfile 2>/dev/null
sudo rm -f /var/swap
swapon --show   # файла больше быть не должно
```

### 9.3. noatime и /tmp

```bash
findmnt -no OPTIONS /     # в списке должно быть noatime
findmnt /tmp              # в идеале tmpfs
```

- Если в опциях корня нет `noatime`, добавь его в `/etc/fstab` в строку с `/` (через запятую к `defaults`) и перезагрузись. Без него система записывает время каждого чтения файла.
- Если `/tmp` не в tmpfs, включи: `sudo systemctl enable tmp.mount` и перезагрузись.

## 10. Автоматические обновления безопасности

```bash
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades   # ответить «Да»
```

Проверка, что всё настроено:

```bash
sudo unattended-upgrade --dry-run --debug 2>&1 | tail -n 20
```

Автоматически ставятся только обновления безопасности Debian, и Pi **не перезагружается сама**: для сетевой инфраструктуры неожиданные перезагрузки хуже. Обновления ядра и прошивки применяй вручную (`sudo apt full-upgrade && sudo reboot`), когда тебе удобно.

## 12. Полный образ SD-карты

Теперь, когда система настроена, сохраним её образ. Если карта умрёт, восстановление займёт минуты, а не вечер.

Копировать всю карту через `dd` невыгодно: получится 128 ГБ, в основном пустого места. Поэтому сохраняем таблицу разделов, загрузочный раздел целиком, а корневой раздел — **только занятые блоки** с помощью `e2image`.

### 12.1. Создание образа

Выключи Pi (`sudo poweroff`), дождись, пока погаснет зелёный индикатор, отключи питание и вставь карту в картридер ноутбука (или ПК с Linux).

Найди карту. **Проверь букву устройства и не монтируй разделы:**

```bash
lsblk -o NAME,SIZE,MODEL,FSTYPE,LABEL
# карта: ~119G, разделы bootfs (vfat) и rootfs (ext4)
```

Ниже карта — `/dev/sdX`. У встроенного картридера это может быть `/dev/mmcblk0`, тогда разделы называются `/dev/mmcblk0p1` и `/dev/mmcblk0p2`.

```bash
DEST=~/pi-images/$(date +%Y-%m-%d)_step20
mkdir -p "$DEST" && cd "$DEST"

# Таблица разделов
sudo sfdisk -d /dev/sdX > partitions.sfdisk

# Загрузочный раздел целиком (он небольшой)
sudo dd if=/dev/sdX1 of=boot.img bs=4M status=progress

# Корневой раздел — только занятые блоки (файл получится «разреженным»)
sudo e2fsck -f /dev/sdX2          # проверка ФС перед снятием образа
sudo e2image -ra -p /dev/sdX2 root.img

sudo chown "$USER": *
sha256sum * > SHA256SUMS
du -sh --apparent-size root.img   # логический размер (= размеру раздела)
du -sh root.img                   # реальное место на диске (= занятым данным)
```

Храни образ **не на keeper**: он занимает несколько гигабайт, а keeper — место для секретов. Подходят стационарный ПК, внешний диск или позже — домашний сервер. Секретов в образе нет, кроме ключей хоста SSH самой Pi.

При копировании образа на другой диск сохраняй разреженность: `cp --sparse=always` или `rsync -S`.

### 12.2. Восстановление

На новую карту `/dev/sdY` размером **не меньше** исходной:

```bash
cd ~/pi-images/ДАТА_step20
sha256sum -c SHA256SUMS

sudo sfdisk /dev/sdY < partitions.sfdisk
sudo dd if=boot.img of=/dev/sdY1 bs=4M status=progress
sudo e2image -ra -p root.img /dev/sdY2
sync
```

Вставь карту в Pi и включи — система загрузится в том же состоянии, в котором был снят образ.

Имеет смысл снимать новый образ после каждого завершённого шага (Pi-hole, шлюз и так далее) и хранить два-три последних.
