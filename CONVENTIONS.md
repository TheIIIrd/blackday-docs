# Как устроены инструкции

Правила, по которым пишется каждый шаг. Нужны, чтобы структура не расползлась и чтобы инструкцию можно было выполнять, не держа в голове контекст соседних файлов.

## Структура файла шага

```markdown
# Шаг NN. Название

**Машина:** что настраиваем
**Система:** ОС и её роль
**Результат шага:** одним абзацем — что будет работать в конце

## Значения, которые нужно подставить
таблица: обозначение → пример → где взять

## 1. Первый раздел
...

## N. Итоговый чек-лист
- [ ] ...

## Отклонения
что разошлось с текстом на реальном железе

## Что дальше
```

## Правила

**Одна команда — один ожидаемый результат.** После команды, которая что-то проверяет, пишется, какой вывод считается нормальным. «Должно быть `throttled=0x0`» полезнее, чем «проверь вывод».

**Опасные команды помечаются до, а не после.** Всё, что необратимо уничтожает данные (`dd`, `blkdiscard`, `mkfs`, `sfdisk`), сопровождается явным предупреждением в той же или предыдущей строке и командой, которая помогает убедиться в правильности устройства.

**Изменения, способные отрезать доступ, применяются с подстраховкой.** Правила файрвола — с таймером автоматического отката, настройки SSH — с проверкой из второй сессии до закрытия первой.

**Решения объясняются.** Если выбран один вариант из нескольких, пишется, почему, и чем расплачиваемся. Инструкция без обоснований невоспроизводима: через полгода непонятно, можно ли отступить от неё.

**Плейсхолдеры вместо реальных значений.** См. таблицу в [README](README.md). Никаких реальных IP, доменов, имён провайдеров и хостеров.

**Чек-лист в конце обязателен.** Он же служит критерием, что шаг действительно закончен.

**Раздел «Отклонения».** Туда дописывается всё, что в реальности выглядело иначе: другое имя сетевого подключения, другой путь в sysfs, переименованный пакет. Это самая ценная часть файла со временем.

**Шапка версии.** В начале файла указывается, на чём и когда проверено:

```markdown
> Проверено: Raspberry Pi OS Lite (64-bit), сентябрь 2026.
```

## Стиль

- Заголовки разделов нумеруются (`## 1.`, `### 1.1.`), чтобы на них можно было ссылаться из других файлов.
- Блоки кода — **всегда** с указанием языка: `bash`, `nft`, `conf`, `ini`, `yaml`, `sshconfig`, `sql`. Для вывода команд, схем каталогов и формул языка нет — для них используется `text`. Блок без языка не пройдёт линтер (правило MD040).
- Команды приводятся по одной на строку, без `&&`-цепочек длиннее двух звеньев: так проще понять, на чём всё сломалось.
- Комментарии внутри команд — на русском.
- Единицы измерения: ГБ/ГиБ различаются там, где это важно (размеры накопителей), Вт и А·ч — для питания.

## Git

- Сообщения коммитов — на русском. Префиксы: `docs:` (новый или изменённый шаг), `ref:` (справочники), `snip:` (конфиги), `fix:` (исправление), `ci:` (автоматика).
- Законченный и проверенный шаг помечается тегом: `git tag step-20-done`.
- Перед публикацией изменений отрабатывает `tools/leakcheck.py` (см. [tools/README.md](tools/README.md)).
